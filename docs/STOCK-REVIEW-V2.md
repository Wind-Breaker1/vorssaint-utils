# 股票复盘第二版需求与验收清单

更新：2026-11-08。状态：第二版功能已实现，核心测试与隔离环境界面验证通过。下文保留需求依据及实施验收清单。

## 目标与已确认范围

核心目标是识别并重复正确操作，发现和减少重复犯错。盈亏保留为结果信息，不参与操作质量判定，不以赚钱、卖在高点或事后股价走势定义正确操作。

- 交易对象：A 股、场内 ETF；交易风格：超短、波段。
- 一轮交易：从建仓到清仓，包含期间的加仓、减仓，允许跨年。
- 操作记录：买卖理由、是否按计划、当时情绪、犯错类型。
- 用户目前没有现成的交易纪律。提供可编辑的基础模板，逐步形成个人规则。
- 放弃交易、继续持有、应该操作却未操作等没有成交的决策，记录在每日复盘中。
- 图表以日 K 为限；数据获取不能阻塞交易记录与复盘。第一版已有可用的免费日 K 与本地缓存。
- 券商为中银证券，目前尚未确认能够导出交割单。第二版不依赖券商导出能力。
- 沿用年度 JSON、可配置数据根目录；iCloud Drive 同步由系统完成。
- 继续使用免费数据，第二版不引入 AI、账户管理或独立云同步服务。

## 评价原则

决策依据与执行情况分开评价：按计划执行可能暴露计划的问题；有依据的临时调整也不自动视为错误。

软件整理记录、计算统计、展示可核对的事实，最终评价由用户确认。文本理由、个人情绪、盘中是否满足条件等，不能仅靠日 K 自动判定。

所有新增评价字段允许暂缺。支持先记成交、后做复盘，历史交易不要求补造当时并不存在的计划或理由。明确区分未评价、无法判断、不适用，均不默认算正确或错误。

## 设计默认值

以下为本次需求分析形成的实现默认值，不表示用户已经提供具体交易纪律或数值阈值。

### 1. 轮次与操作

- 同一证券持仓从零变为正数时开始一轮，卖至零时结束；清仓后再次买入开始新一轮。尚未清仓的轮次标记进行中。
- 从全部年度成交推导轮次，跨年不拆断。分红、份额调整作为事实保留，不计入买卖决策次数。
- 一轮内分别评价建仓、加仓、减仓、清仓；整轮总结不能覆盖或抹掉单次操作问题。
- 同一次决策的多笔成交允许手动合并评价，保留所有原始成交。不同证券、买卖方向或轮次不能合并；不只凭价格相同自动合并。
- 轮次记录超短或波段，可补充自定义策略标签。风格调整记录时间与原因，不能通过事后更名改写原始计划。
- 编辑或删除历史成交后重算轮次，保留仍有效的操作评价；关系失效时提示重新关联，不能悄悄丢弃评价。

### 2. 买卖记录与计划

- 买卖理由支持自定义标签和文字说明；个人情绪与第一版的市场情绪数据分开存储和展示。
- 执行情况支持按计划、合理调整、偏离计划、无计划、无法判断、未评价。合理调整须能记录新信息及调整依据；无计划只是事实状态，是否属于错误取决于适用的个人规则。
- 犯错类型允许多选、补充说明、自定义；没有勾选错误不代表已经确认操作正确。
- 操作关联当时的计划版本。计划更新保留版本、记录时间、变更原因；事后分析单独填写。
- 操作发生时间与信息录入时间分开记录。历史补录或事后补写明确标注，不能显示为有同期记录证明的事前计划。
- 规则、标签、计划修改后，历史评价仍保留当时使用的内容与版本。

### 3. 基础规则模板

提供超短、波段两份可编辑模板。模板作为复盘提示，用户可启用、停用、增加和修改条目，不预设仓位比例、止损幅度或盈利目标。

| 环节 | 基础提示 |
| --- | --- |
| 入场 | 当时的买入依据是什么？是否符合自己设定的触发条件？ |
| 风险 | 是否明确本次操作的风险边界和判断失效条件？ |
| 加减仓 | 为什么改变持仓？是否满足原定条件或记录了调整依据？ |
| 退出 | 卖出的原因是什么？是否符合退出条件或调整后的计划？ |
| 纪律 | 适用的个人规则是否遵守？如有偏离，证据与原因是什么？ |

每条适用规则分别记录符合、违反、无法判断、未评价；不适用规则单独列出。对计划本身的问题记录改进建议，保留原版本用于回看。

### 4. 没有成交的决策

- 在每日复盘内增加可选的决策条目，不增设独立的日常录入工作流。
- 条目包含决策类型、相关证券或市场、关联计划、原因、情绪、规则评价、错误类型和改进措施；按需要填写。
- 类型包括等待、放弃买入、继续持有、应操作但未操作，也可自定义。
- 可以关联已有轮次；没有持仓时不强行创建交易轮次，不生成虚构成交。
- 普通复盘文字继续保留。只有用户明确录入的决策条目进入相关统计，不从自由文本自动推断。
- 这类样本与实际买卖分别展示，不能把没有记录的交易日当成正确空仓，也不能根据后续上涨认定当时错过机会。

### 5. 执行质量统计

首页以执行质量、待复盘事项和错误改进为主，盈亏作为辅助结果查看。不设置凭空加权的综合分，不将收益计入规则符合率。

| 指标 | 口径与用途 |
| --- | --- |
| 复盘覆盖 | 展示适用规则均已作出评价的操作数、全部操作数及未完成数量；无法判断仍单独显示。买卖与无成交决策分别计算。 |
| 规则符合率 | 每条规则的符合数 /（符合数 + 违反数）。同时列出无法判断、未评价、不适用数量；分母为零时显示无可判断样本。 |
| 计划执行分布 | 分别统计按计划、合理调整、偏离计划、无计划、无法判断、未评价，不把合理调整并入偏离计划。 |
| 错误分布 | 按操作计数，同一操作相同错误只计一次；多种错误可同时存在，说明各类占比之和可能大于 100%。 |
| 错误复发趋势 | 展示错误发生次数及适用的已评价操作样本数；按时间比较，不把交易变少造成的次数下降直接认定为改善。 |
| 情绪关联 | 展示不同情绪下的错误分布和样本数，支持回到原始案例；不推断因果。 |
| 正确操作案例 | 用户主动确认并附依据，允许包含亏损操作，支持收藏和按规则、风格筛选。 |
| 改进跟踪 | 从错误记录改进措施与建立日期，回看后续案例和复发情况；不自动保证措施有效。 |

支持按日期、超短/波段、证券、规则、错误类型筛选。操作统计按操作发生日期归属，轮次汇总明确区分进行中与已完成；同一轮跨年不重复计数。每项结果能下钻到具体记录和计算样本。

### 6. 日 K 与市场背景

- 复用第一版免费日 K、本地缓存和买卖标记；支持从轮次查看相关操作、理由及评价。
- 展示已有的当日涨停梯队、板块和市场情绪快照作为复盘背景；缺失则显示缺失，不用其他日期数据替代。
- 日 K 不用于推断盘中触发先后或超短买卖时机是否正确。收盘数据不得显示为盘中已经知道的决策依据。
- 本版不新增分钟行情、行情回放或复杂绘图工具。

### 7. 快捷录入与持久化

- 保留手工成交录入和 CSV 导入，完善复制上一笔、从持仓录入卖出等操作；复制时不自动继承旧操作评价和成交编号。
- 中银证券导出能力尚未验证，不宣称支持其专用格式，不依赖券商登录、自动抓取或截图识别。
- 成交事实继续按年保存到 trades；复盘、计划版本、评价及无成交决策按年保存在 reviews。使用稳定 ID 跨年关联，不创建每笔成交或每轮交易一个文件。
- 共用规则和标签集中存一份 JSON，随数据根目录一起同步；被引用的历史版本保留。
- 第一版数据可读，新增字段缺失时为未填写。升级前备份，明确 schemaVersion；恢复、迁移、外部修改检测必须覆盖新增内容。
- 修改规则或统计口径时，不覆盖历史事实，不悄悄将旧记录重判为正确。

## 使用第二版

2026-11-08 界面改进：灵动岛「功能列表」新增股票复盘入口，可在灵动岛设置调整排序及快捷入口。每日复盘正文支持原位输入、保存与撤销，也支持 Command-S；有未保存内容时保留当前日期，切换工作台页面后保留内存草稿，切换数据目录前须保存。市场快照改为紧凑读数、并排涨停表与轮动矩阵，涨停支持梯队和文字筛选。执行质量的规则与趋势统计按需展开。

工作台导航按用户反馈精简：不显示独立「交易轮次」和「市场快照」页面。交易轮次仍在后台从成交推导，用于操作关联和统计；操作评价从执行质量、成交记录或每日复盘进入。市场数据继续后台采集，可在每日复盘按需展开已保存背景或为当天请求数据。

1. 打开 `build/stage.noindex/Vorssaint (Developer).app`，启用「股票复盘」后打开工作台。默认首页为「执行质量」。
2. 在「规则与标签」编辑超短、波段模板，启停规则，添加理由、情绪和错误标签。
3. 在「成交记录」中从某笔买卖的操作菜单打开评价，或在「每日复盘」点击对应成交旁的「评价」。填写理由、计划版本、执行与情绪，在「规则与错误」核对各项并确认已复盘。可以点击「添加当前风格的规则」。
4. 同一次决策的拆单可以在「关联成交」合并评价，当前限同日、同轮次、同买卖方向；原始成交保留。
5. 「每日复盘」→「记录无成交决策」，填写等待、持有、放弃买入或应操作未操作等判断，也支持自定义名称。
6. 「执行质量」将买卖与无成交决策分开统计，支持日期、风格、证券、规则版本、错误、情绪和执行情况筛选。点击统计行缩小样本，打开原操作核对；改进跟踪可以展开后续样本。
7. 正确操作案例由你主动确认并填写依据，可以包含亏损操作。未评价、无法判断、不适用分别列出；未选择适用规则不算复盘完成。
8. 从「自选与图表」查看日 K、买卖点和成交量。行情缺失不阻塞复盘；轮次关联由系统在后台计算。
9. 成交列表支持复制为新成交，持仓页支持记卖出。复制不继承成交编号、计划或评价；价格与数量需要按实际核对。

## 存储与历史保护

- 成交继续保存在 `trades/YYYY.json`；`reviews/YYYY.json` 使用 schemaVersion 2，加入计划版本、评价、无成交决策和轮次备注。共用规则与标签保存在 `rules.json`。
- 第一版缺少的新字段按未填写处理。升级写入前备份原始 JSON；新增内容参与外部修改检测、iCloud 未下载检测、迁移与恢复。
- 轮次从全部年度成交推导，不生成逐笔或逐轮文件。评价归属于操作发生日期；跨年移动使用事务写入保护。
- 修改成交日期、时间、证券、方向、价格、数量或费用后，原评价与快照保留，标记待重新核对并退出有效统计；明确核对保存后恢复。
- 删除起始成交导致轮次标识变化时，原备注保留在「待关联」区域，可以关联到尚无备注的新轮次。
- 计划内容变更需要原因并保留版本；取消计划不删除历史。事后验证结果不覆盖原计划。第一版未保存过的历史版本无法还原，界面明确说明。
- 评价记录实际录入时间，晚于操作或缺少时间依据时标记事后补记；选用晚于操作的计划版本会提示。行情采集与复盘正文保存不覆盖独立保存的评价。
