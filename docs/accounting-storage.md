# 简化的记账 JSON 存储

所有数据放在设置页选择的保存目录。可选本地目录或 iCloud Drive 文件夹；
各设备选择同一 iCloud 文件夹，由系统负责上传、下载与文件同步，无单独云端配置。
默认路径为 `~/Library/Mobile Documents/com~apple~CloudDocs/Vorssaint/Accounting`，
首次使用自动创建子目录。笔记默认位于同级 `Notes` 目录。已有自选保存位置继续使用，
iCloud Drive 不可用时提示启用或选择其他目录，不创建假云盘目录。

- `YYYY.json`：schemaVersion=2、year、entries；每笔包含 UUID、整数分金额、日期、分类 ID/名称/类型及备注。
- `categories.json`：完整分类列表，包含名称、类型与停用状态。
- 按 UTC 年份划分文件，界面按本地日历显示月份。

所有读写在串行队列执行，并以 NSFileCoordinator 协调整个账本目录。
写入使用原子替换和 0600 权限。每 30 秒刷新，保存后和切换月份时也刷新。
每次只写发生修改的年度文件，月度查询只读取覆盖该月份的 UTC 年度文件，普通刷新不重写账目。
分类重命名通过 categories.json 展示到历史账目，原账目仍内嵌分类信息。

没有账目版本链、删除墓碑或自动分支合并。iCloud 出现未解决的文件版本冲突时，
保留系统提供的所有冲突版本，报错并暂停访问相关文件，不静默选择或解决版本。
用户需要在文件层处理冲突后重试。不保证两端同时离线编辑同一年度文件可自动合并。
未下载的文件请求下载并提示等待，绝不按空账本覆盖。

更换保存位置要求选择独立空目录，复制全部 JSON 原始字节并逐个校验，打开目标仓库成功后切换配置。
原 JSON 始终保留，设置页保存旧目录记录；确认迁移结果后，可通过“更改保存位置”之后的“删除旧数据”按钮手动清理；没有旧目录记录时按钮禁用。
旧目录记录持久化，重启后仍可操作。清理只删除 JSON，不删除目录中的其他文件，也不允许清理当前保存位置。
不合并目标已有数据，不覆盖文件。复制或校验失败保留源文件。
跨年编辑先写新年度再移除旧年度；中断可能留下可检测的重复记录，不静默丢弃记录。

不再读取或迁移旧 SQLite，不再包含记账 SQLite 导入代码与对应测试。
用户已有 SQLite 文件不会被删除。
不再解析或转换旧 revision JSON，仅支持当前年度 entries 格式。

`./build.sh --test-suite=accounting` 使用临时目录验证金额、分类、分页、跨年编辑、
普通 JSON 格式、删除、损坏文件保护、JSON 文件迁移及共享目录刷新。
真实 iCloud 双设备的系统运输与冲突提示需要设备验收。
